# 撤资（供货商结账）

供货商想取回本金与利润时，调用：

```text
disinvestProof(proofid, shares, gate, trader, signature)
```

## 撤货核心规则

1. **核对归属**：必须由凭证所有者本人发起（无「签名代撤」）；
2. **按历史进货数量按比例返还**：
   - 本次撤出份额占凭证总份额的比例为 `X%`；
   - 按 `X%` 退还**最初记在凭证上的进货数量**；
   - **与当前货架价无关**；
3. **结算利润**：当前货架净值相对历史净值的增量，按六方分账规则分配；
4. **扣除撤货费（`disinvestFee`）**：留在货架内，提高其余供货商单位份额净值（变相复利）；
5. **同步 TTS 解押**：仅当该凭证曾记过 TTS 算力（承诺型货架）且本次对应 `disinvestTTSValue > 0` 时，才 `unstake` 铸造 TTS。

## 为什么能做到「零无常损失」

传统 AMM 撤流动性时，双币数量会随中间价格变形：价值可能涨了，但某一侧数量变少——这就是无常损失。

TTSWAP 的做法：

- 你存入 10,000 枚某商品，凭证记录「历史进货 = 10,000」；
- 无论货架价格如何波动，撤货时都按凭证比例返还对应枚数；
- 期间手续费、福利注入等，作为**净值增量**额外结算。

**结果**：撤货时得到的商品数量通常是「本金 + 利润」，而不是被价格路径扭曲后的双币组合。机制细节见 [三重防护](./LP)。

## 撤货切片（Disinvest Chips）

巨鲸一次性撤太多货，会冲击其他供货商与顾客。每条货架有配置项 `getDisinvestChips`：

- 单次撤货的数量 / 价值不得超过切片上限；
- 超过则回滚（如 `TTSwapError(26)` / `TTSwapError(27)`）。

作用：平滑对货架深度的冲击，降低砸盘牵连。

## 撤货示例

设 Bob 持有：

- `shares = 10000`，历史进货 `invest = 10000` 枚；
- 期间货架已累积交易手续费；
- Bob 撤 50%（5000 份）。

协议大致执行：

1. 历史比例返还：`10000 × 5000 / 10000 = 5000` 枚；
2. 计算当前净值与净利润 Δ；
3. 扣 `disinvestFee`；
4. 六方分账（供货商通常可拿到 `liquidFee` 等档位份额）；
5. Bob 账户：`5000` 枚本金对应商品 + 利润份额 +（若有）TTS 收益；
6. 凭证更新为剩余 `shares = 5000`，`invest = 5000`。

## TTS 挖矿何时兑现

| 动作 | TTS 算力 | 当下是否拿到 TTS |
|:--|:--|:--|
| 补货（`isPromised`） | 立刻记账 | 否（等日增发累积） |
| 持续持有凭证 | 按算力占比参与每日增发 | 否（收益挂在凭证上） |
| 撤货 | 按撤出份额等比退回算力 | **是**，`unstake` 铸造到账 |

只撤一部分时，剩余份额继续挖矿；全部撤出则算力清零，相当于退出矿池并结算最后一批收益。

## 权限说明

- 仅 **proof 所有者本人**可调用 `disinvestProof`；
- 协议通过 `S_ProofKey(trader, currentgood).toId() == proofid` 核对；
- 即使持有他人签名，也不能代其撤货——撤货涉及资金返还，协议刻意禁止外人代操作。
