# 投资（单币补货）

传统 DEX 补货往往要同时准备两种等值商品。TTSWAP 更贴近真实商场：**只带一种商品来，也能补货**。

调用：

```text
investGood(goodKey, packed(0, quantity), ...)
```

协议**一律按货架当前价**自动计价。

## 开新货架 vs 补货

商场里每种商品只能挂一次货架。参与流动性有两条路：

| 方式 | 谁用 | 场景 |
|:--|:--|:--|
| **`initGood`** | 任何人 | 第一次为某种 Token 开货架，自定初始价 |
| **`investGood`** | 任何人 | 给已存在的货架追加存货 |

### 开新货架要点（`initGood`）

你需要告诉商场：上架什么商品、放多少件（初始库存 $Q_0$）、标多少初始总价值（$V_0$）。

合约会检查（节选）：

- 初始价值与库存落在协议允许区间（过小 / 过大都会 revert）；
- 该商品此前**没有**开过货架。

通过后，你成为该货架的**品牌方（Owner）**，并获得初始供货凭证。注意：

- **开货架本身不自动挖 TTS**；
- 只有后续在标记为「承诺型（`isPromised`）」的货架上 `investGood` 时，才记 TTS 算力；
- 关键发运营期内，品牌方可享有操作人分佣等权益（详见白皮书商品上架章节）。

## 单币补货规则

| 规则 | 说明 |
|:--|:--|
| **按池内现价** | 协议按 `V/Q` 折算本批货价值；申报价高于池价会 revert |
| **最小价值** | 单次补货折算价值须 ≥ $10^{12}$（过小会被拒） |
| **凭证累加** | 同一地址、同一货架多次补货，累加到同一张供货凭证 |

## 单币补货的 6 步流程

以 Bob 给某货架补货为例：

1. **读取货架状态**：当前市场价值 $V$、库存 $Q$、累计进货 $I$；
2. **按当前价折算**：扣除投资费后，计算本次贡献价值；
3. **读取放大倍数（`enpower`）**：按池深度动态缩放，上限由 `power` 配置；
4. **虚拟放大**：真实进货按倍数记入虚拟陈列深度，提升可服务交易的深度；
5. **计算份额**：按比例给 Bob 增发 / 累加供货凭证份额；
6. **写回货架 + 条件性 TTS 记账**：仅当货架标记 `isPromised` 时，`stake` 记入 TTS 算力。

**价格中性**：补货前后，池内单位定价由公式保证不会因单笔补货剧烈偏移。

## 为什么单币补货不会被轻易套走其它商品

「只补一般商品再套走 USDT / ETH」是常见疑虑。协议用 **安全线（safeLine）** 限制单笔交易对货架深度的冲击：卖压把库存推到上界、或买盘抽到下界时，收银台会拒收。详见 [三重防护](./LP)。

### 商场直觉

> 供货商给货架送水：实际送了 200 瓶，虚拟陈列了 800 瓶，货架最多按「实际 + 虚拟」容量承接。  
> 若无人来买，别人想再往里塞 500 瓶换走硬通货，老板会拒收——**货架满了**。  
> 只有消费者买走一部分，腾出空位，卖单才有空间。

这与 TTSWAP 一般商品的 `safeLine` 行为同构。

## 供货即挖矿（条件）

| 动作 | 是否记 TTS 算力 |
|:--|:--|
| `initGood` 开货架 | **否** |
| `investGood` 补货 | **仅当货架 `isPromised`** |
| `disinvestProof` 撤货 | 有算力则按撤出份额 `unstake` |

算力按**贡献价值**（`investvalue`）记账，不按枚数；每日增发按全网活跃 LP 算力占比分配，收益一般在撤货时兑现。更多见 [撤资](./Devest) 与 [代币经济](../Tokenomics/Overview)。
